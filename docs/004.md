# Troubleshooting Qualcomm QCNFA765 (WCN6855) Self-Managed Regulatory Domain on Debian

## Overview

The **Qualcomm QCNFA765** (chipset **WCN6855**) uses the `ath11k_pci` Linux kernel driver. Unlike older Wi-Fi cards that let the Linux kernel (`cfg80211`) manage regional frequency rules, the QCNFA765 uses a **self-managed regulatory domain**. 

Because regulatory compliance is enforced directly inside closed-source firmware, standard Debian configuration tools—such as `iw reg set`, `/etc/default/crda`, or `ieee80211_regdom=` module parameters—are ignored by the hardware.

---

## Root Cause: Why Is It Locked?

### 1. Regulatory & Certification Compliance
* **Strict Radio Laws:** Regulators like the FCC and ETSI require hardware manufacturers to prevent end users from easily bypassing regional frequency and transmit-power limits via software commands.
* **Wi-Fi 6E (6 GHz) Enforcement:** Because 6 GHz spectrum rules vary drastically across countries, Qualcomm moved regulatory enforcement out of the open-source kernel and into signed firmware (`regdb.bin`) to obtain global Wi-Fi 6E certification.

### 2. Default Fallback Behavior on Linux
* **Missing BIOS/SMBIOS Flags:** Laptop OEMs typically configure regional BIOS flags for Windows drivers. On Linux, `ath11k` often fails to read a valid region from SMBIOS and falls back to the restrictive `00` (World) domain.
* **Restrictive `00` World Mode:** In `00` mode, the card completely disables 6 GHz channels and blocks several 5 GHz (including DFS) channels to guarantee compliance anywhere in the world.
* **Outdated Debian Firmware:** Debian Stable ships older versions of `firmware-atheros`, which can contain outdated `regdb.bin` databases or firmware bugs that prevent the card from updating its region dynamically.

---

## Symptoms

* Running `iw reg get` shows `country 00: DFS-UNSET` with `(self-managed)` next to the `phy#0` device.
* `sudo iw reg set <COUNTRY_CODE>` executes without error, but `iw reg get` remains stuck on `00`.
* Missing 5 GHz channels or inability to detect/connect to Wi-Fi 6E (6 GHz) networks.
* `hostapd` fails to start when configured to broadcast on 5 GHz DFS or 6 GHz channels.

---

## Solutions & Workarounds

Because the lock is hardcoded in firmware, there is no permanent override via standard Linux networking tools. Use the following methods to resolve or work around the restriction.

### Method 1: Update `firmware-atheros` (Recommended)
Newer firmware releases from upstream `linux-firmware` resolve several regional database bugs for the WCN6855.

1. Enable Debian Backports (if running Debian Stable) or pull from a newer release repository.
2. Install the updated firmware package:
   ```bash
   sudo apt update
   sudo apt install -t bookworm-backports firmware-atheros
   ```
3. *(Alternative)* Manually download the latest `ath11k/WCN6855/hw2.1/` files from the official [Linux Kernel Firmware Repository](https://kernel.org) and place them in `/lib/firmware/ath11k/WCN6855/hw2.1/`.
4. Reboot the system for the new firmware to load.

### Method 2: Dynamic Unlock via Router `802.11d` Beacons (Client Mode)
When operating in client mode, the QCNFA765 firmware listens for `802.11d` country information elements broadcast by nearby Access Points (APs).

1. Ensure your wireless router or AP has **802.11d** (Country Code broadcast) enabled in its wireless settings.
2. Scan or connect to the 2.4 GHz or lower 5 GHz band of the router.
3. Once the card receives the country beacon, the firmware will automatically unlock the remaining 5 GHz and 6 GHz channels for your region until the next reboot.

### Method 3: Configure Safe Channels for AP / Hotspot Mode (`hostapd`)
If you are using the card as a Wi-Fi hotspot, `hostapd` cannot force the card out of `00` mode prior to initialization.

1. Edit `/etc/hostapd/hostapd.conf` to use universally permitted channels:
   * **5 GHz:** Use non-DFS channels `36`, `40`, `44`, or `48`.
   * **2.4 GHz:** Use channels `1` through `11`.
2. Explicitly enable `802.11d` in `hostapd.conf` so the interface advertises your region once active:
   ```ini
   country_code=ID
   ieee80211d=1
   ```
   *(Replace `ID` with your two-letter ISO country code).*

### Method 4: Manual `regdb.bin` Replacement (Advanced / Fragile)
If upstream firmware updates still fail to unlock required frequencies in an offline environment:

1. Obtain or compile a modified `regdb.bin` tailored for `WCN6855`.
2. Back up the existing database:
   ```bash
   sudo cp /lib/firmware/ath11k/WCN6855/hw2.1/regdb.bin /lib/firmware/ath11k/WCN6855/hw2.1/regdb.bin.bak
   ```
3. Replace `/lib/firmware/ath11k/WCN6855/hw2.1/regdb.bin` with the modified file and reboot.

> **Note:** Any future updates to the `firmware-atheros` package via `apt` will overwrite manual changes to `/lib/firmware/`.

---

## Verification

After applying a fix or connecting to an `802.11d`-enabled router, verify the active regulatory state:

```bash
iw reg get
```

Look for the `phy#0 (self-managed)` section. If successful, `country 00` will be replaced by your local country code (e.g., `country ID:` or `country US:`) along with expanded frequency ranges and higher `mW`/`dBm` transmit power limits.
