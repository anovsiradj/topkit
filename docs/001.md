# Knowledgebase Guide: Fixing Wi-Fi Not Working After Hibernate / Suspend on Linux (Qualcomm QCNFA765)

## Overview
On certain enterprise laptops (such as the HP EliteBook 845 G8), the Qualcomm QCNFA765 Wireless Network Adapter fails to initialize after waking up from deep sleep or hibernation. Because the network device state gets stuck in an unpowered state at the hardware/driver level, restarting NetworkManager manually yields no results.
The permanent solution is to force the system to cleanly unload the Qualcomm kernel module (ath11k_pci) right before hibernation and reload it immediately upon wake-up.

## Symptoms
* Wi-Fi drops completely after resuming the laptop from a suspended or hibernated state.
* The system tray icon shows "Device not ready".
* Running sudo systemctl restart NetworkManager does not restore the connection.


## Technical Cause
The ath11k_pci driver module has known power management conflicts with modern hardware power states.
When the system powers down into a hibernate pool, the card does not reset its own internal firmware registers upon receiving the wake signal.

## Step-by-Step Resolution

### 1. Verify Your Hardware
Confirm that your laptop is utilizing the affected Qualcomm chip. Open a terminal and run:
```sh
lspci | grep -i network
```

Expected output:

```
Network controller: Qualcomm Technologies, Inc. QCNFA765 Wireless Network Adapter (rev ...)
```

### 2. Create the Kernel Module Automation Script

We will place an execution hook inside systemd's power state directory to catch both pre (sleep) and post (wake) triggers.

Open your terminal and create a custom sleep hook script:

```sh
sudo nano /usr/lib/systemd/system-sleep/ath11k-hibernate-fix
```   

Copy and paste the following bash script into the text editor:

```sh
#!/bin/sh
case "$1" in
    pre)
        echo "Unloading Qualcomm ath11k driver before hibernation..."
        systemctl stop NetworkManager
        modprobe -r ath11k_pci
        modprobe -r ath11k
        ;;
    post)
        echo "Reloading Qualcomm ath11k driver after waking up..."
        modprobe ath11k
        modprobe ath11k_pci
        sleep 2
        systemctl restart NetworkManager
        ;;esac

```
   
Save the file and exit (Ctrl+O, press Enter, then Ctrl+X).

### 3. Apply Executive Permissions
The system will ignore the script if it isn't explicitly flagged as executable. Enable it by running:

```sh
sudo chmod +x /usr/lib/systemd/system-sleep/ath11k-hibernate-fix
```

## 4. Verification & Testing

1. Trigger a standard system hibernation or close your laptop lid.
2. Turn the machine back on and log into your desktop interface.
3. Allow 3 to 5 seconds for the post-resume sequence to insert the module and cycle the NetworkManager service.
4. The Wi-Fi interface should automatically power on and re-authenticate to your saved networks.

## Troubleshooting
If the adapter remains unresponsive after applying the fix, check the system kernel rings to verify if the firmware loaded properly:

```sh
dmesg | grep ath11k
```

Look for any lines containing firmware boot failed or failed to resume.
