# Troubleshooting: Intermittent 5 GHz Wi-Fi Detection on Debian XFCE

## Issue Summary
The system intermittently fails to detect 5 GHz Wi-Fi networks (including Android tethering hotspots). 

### Behavior and Pattern
* Connecting to a 5 GHz network and disconnecting allows other 5 GHz networks to remain visible.
* Connecting to a 2.4 GHz network and disconnecting causes all 5 GHz networks to completely disappear from the NetworkManager menu.

## Affected Hardware & Drivers
* **Hardware:** Qualcomm Technologies, Inc. QCNFA765 Wireless Network Adapter `[17cb:1103]`
* **Kernel Driver:** `ath11k_pci`

## Root Cause
This issue is caused by a known power management and channel scanning bug in the `ath11k` Linux kernel driver state machine.
When the card connects to a 2.4 GHz network, the driver optimizes radio usage by idling the 5 GHz chain. Upon disconnection, the driver fails to wake the 5 GHz radio components back up, leaving the card stuck in a 2.4 GHz-only state.

---

## Diagnostic & Validation Steps

### 1. Confirm Hardware Identification
Verify the wireless card model matches the affected chipset:
```bash
lspci -nn | grep -i net
```
*Expected Output:*
> `01:00.0 Network controller: Qualcomm Technologies, Inc QCNFA765 Wireless Network Adapter [17cb:1103] (rev 01)`

### 2. Manual Verification (The Reset Test)
When 5 GHz networks disappear after disconnecting from a 2.4 GHz network, force-reload the kernel module to verify the state issue:
```bash
sudo modprobe -r ath11k_pci && sudo modprobe ath11k_pci
```
*Result:* If 5 GHz networks reappear within 5–10 seconds, the driver state bug is confirmed.

---

## Permanent Solution: Disable Driver Idle Power Saving

To resolve this permanently, you must pass a kernel parameter to the `ath11k_pci` driver to prevent it from putting the 5 GHz radio chain into an unstable idle state.

### Step-by-Step Implementation

1. **Open the GRUB configuration file** using a terminal text editor with administrative privileges:
   ```bash
   sudo nano /etc/default/grub
   ```

2. **Locate the kernel parameters line**:
   Find the line starting with `GRUB_CMDLINE_LINUX_DEFAULT`. It typically defaults to:
   ```text
   GRUB_CMDLINE_LINUX_DEFAULT="quiet splash"
   ```

3. **Append the fix parameter**:
   Add `ath11k_pci.disable_idle_ps=1` inside the quotation marks:
   ```text
   GRUB_CMDLINE_LINUX_DEFAULT="quiet splash ath11k_pci.disable_idle_ps=1"
   ```

4. **Save and Exit**:
   * Press `Ctrl + O` then `Enter` to save changes.
   * Press `Ctrl + X` to close the editor.

5. **Update the GRUB bootloader** to apply the configuration:
   ```bash
   sudo update-grub
   ```

6. **Reboot the system**:
   ```bash
   sudo reboot
   ```

## Verification After Fix
Once the system reboots, test the behavior again:
1. Connect to a 2.4 GHz network.
2. Disconnect from it.
3. Verify that 5 GHz networks (and Android 5 GHz tethering) remain consistently visible in the XFCE NetworkManager applet.
